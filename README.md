# Minecraft Bot (Node.js + Mineflayer)

Headless-бот для Minecraft Java Edition. Работает без окна игры: подключается к серверу, воюет, ест, лечится, охраняет точку, пишет логи и управляется из чата, CLI и Web GUI.

Подробные примеры команд и разбор состояний — в [`FUNCTIONS.md`](FUNCTIONS.md).

---

## 1. Назначение

- Управление ботом из трёх источников: **чат Minecraft**, **CLI** (при TTY), **Web GUI** (`http://localhost:3000`).
- Автоматическое поведение без единой команды: атака враждебных мобов, еда, лечение, экипировка брони и оружия, охрана точки, авто-возрождение, авто-подключение.
- Устойчивость: reconnect с экспоненциальной задержкой, `uncaughtException` не роняет процесс, занятый web-порт не мешает игре.
- Диагностика: суточные логи, heartbeat, счётчики расходов, отчёт по зельям.

## 2. Требования

| Требование | Значение |
|------------|----------|
| Node.js | ≥ 18 (проверено на 24.21.0) |
| npm | ≥ 9 |
| Minecraft-сервер | Java Edition, проверено на 1.21.11, `offline`-режим |
| ОС | Windows (основная), Linux/macOS (совместимо) |
| Свободный порт | `webPort` из `config.json` (по умолчанию 3000) |

Ник бота не должен совпадать с ником игрока — иначе сервер выкинет одного из них.

## 4. Быстрый запуск

Одна команда, зависимости ставятся автоматически:

```bat
start.bat
```

Другие варианты:

| Команда | Платформа | Что делает |
|---------|-----------|------------|
| `start.bat` | Windows | Устанавливает зависимости при отсутствии, запускает бота в текущем окне, `pause` в конце |
| `start-debug.bat` | Windows | То же + лог в консоль через `more`, подходит для TTY-режима CLI |
| `start-bg.bat` | Windows | Фоновый запуск, лог в `bot_ГГГГММДД_ЧЧММ.log`, PID в `bot.pid` |
| `start.sh` | Linux/macOS | Устанавливает зависимости при отсутствии, запускает бота |
| `npm start` | все | `node bot.js` |
| `npm run dev` | все | `node --watch bot.js` — автоперезапуск при правках |
| `npm test` | все | `node tests/smoke.js` — 12 проверок |
| `npm run debug` | все | `node --inspect bot.js` — отладчик Node на порту 9229 |

Права для `start.sh`: `chmod +x start.sh`.

Остановка: `quit` в чате/CLI/Web, либо `Ctrl+C` в окне, либо `taskkill /IM node.exe /F` для фонового запуска.

## 5. Конфигурация

Файл `config.json`. Все поля:

| Поле | Тип | Значение по умолчанию | Описание |
|------|-----|----------------------|----------|
| `host` | string | — | IP сервера |
| `port` | number | 25565 | Порт Minecraft |
| `username` | string | — | Ник бота (не должен совпадать с ником игрока) |
| `version` | string \| false | false | `false` = автоопределение версии сервера |
| `auth` | string | offline | `offline` / `microsoft` |
| `reconnectDelay` | number | 5000 | Fallback-задержка (основная — `BACKOFF_SCHEDULE`) |
| `maxReconnectAttempts` | number | -1 | `-1` = бесконечно |
| `followDistance` | number | 3 | Дистанция следования в блоках |
| `prefix` | string | ! | Префикс чат-команд (только для `source === 'game'`) |
| `guardRadius` | number | 8 | Радиус охраны по умолчанию |
| `combatRadius` | number | 10 | Радиус авто-атаки |
| `autoEatStartAt` | number | 14 | Порог голода для авто-еды |
| `autoHealThreshold` | number | 10 | HP для зелья/еды |
| `autoHealCriticalThreshold` | number | 6 | HP для срочного золотого яблока |
| `webPort` | number | 3000 | Порт Web GUI |
| `webToken` | string | "" | Токен доступа (пусто = только localhost) |
| `debug` | bool | false | Включает `[DBG]`-логи раз в ~5 сек |

Переменная окружения `WEB_PORT_OVERRIDE` перекрывает `webPort` — используется smoke-тестом, когда 3000 занят.

Детали применения порогов лечения: `autoHeal()` дёргается из `physicsTick` каждый 20-й тик при `bot.health < 14`; внутри него `hp < autoHealThreshold` → зелье, `hp < autoHealCriticalThreshold` → золотое яблоко, `food < 14` → еда.

## 6. Полный функционал

### 6.1. Автоматические функции (без команд)

| Функция | Триггер | Модуль | Что делает |
|---------|---------|--------|-----------|
| Авто-подключение | старт `bot.js` | `bot.js` → `createBot()` | Подключается к `host:port`, грузит плагины |
| Reconnect с backoff | `end` | `bot.js` | 5с → 10с → 30с → 60с → 120с, сброс индекса в `login` |
| Авто-возрождение | `death` | `bot.js` | Чистит таймеры, снимает охрану/бой/следование, `bot.respawn()` через 1с |
| Авто-экипировка брони | `spawn`, `playerCollect` | `src/equipment.js` + armor-manager | `bot.armorManager.equipAll()` (с задержкой 500 мс при подборе) |
| Авто-экипировка оружия | `spawn`, `playerCollect`, каждый 20-й тик | `src/equipment.js` | Меч приоритетнее топора, тир и `sharpness` учитываются |
| Авто-атака враждебных | каждый 10-й тик | `src/combat.js` | `type === 'hostile'` в радиусе `combatRadius` (или `guardRadius + 4` при охране) |
| Watchdog боя | каждый 10-й тик | `src/combat.js` | `pvp.stop()`, если бой > 30с и цель не двигается |
| Авто-еда | `physicsTick` (mineflayer-auto-eat) | `src/consumables.js` | При голоде < `autoEatStartAt`, яблоки/зелья забанены |
| Авто-лечение | каждый 20-й тик при `hp < 14` | `src/consumables.js` | Зелье → золотое яблоко → обычная еда, кулдауны 10с / 5с |
| Охрана точки | `!guard` | `src/guard.js` | Возврат при уходе > 1.5 блока, не мешает бою |
| Heartbeat | каждые 30 с | `src/logger.js` | `[HEARTBEAT] uptime=N, tick=N, mem=N, hp=N, connected=true` |
| Суточные логи | при каждой записи | `src/logger.js` | Новый файл `logs/bot-ГГГГ-ММ-ДД.log` каждый день (ротации по размеру нет) |

### 6.2. Команды (единый список для чата, CLI, Web)

В чате Minecraft префикс `!` обязателен (`config.prefix`); в CLI и Web вводятся без префикса.

| Команда | Аргументы | Действие |
|---------|-----------|----------|
| `follow <ник>` | ник игрока | Следование за игроком (сбрасывает охрану) |
| `stop` | — | Остановить следование, охрану, бой |
| `guard [радиус]` | число (по умолч. `guardRadius`) | Охрана текущей точки |
| `unguard` | — | Снять охрану немедленно |
| `attack` | — | Атаковать ближайшего враждебного |
| `peace` | — | Прекратить бой, выключить авто-атаку |
| `armor` | — | Надеть лучшую броню |
| `sword` | — | Взять лучшее оружие |
| `status` | — | HP, Food, Pos, Guard, Combat, Target |
| `stats` | — | Счётчики расходов (зелья, яблоки, еда) + чёрный список |
| `potions` | — | Список зелий в инвентаре (id, displayName, components) |
| `clearpotions` | — | Сбросить чёрный список зелий |
| `help` | — | Список команд |
| `quit` | — | Завершить бота |

### 6.3. CLI

- Промпт `bot> ` в TTY-режиме.
- Ввод без префикса `!`: `status`, `guard 8`, `quit`.
- Логи дублируются в stdout только при TTY — при перенаправлении в файл остаётся только лог-файл.
- При `stdin` не-TTY (пайп, редирект) CLI выключается: `[CLI] Неинтерактивный режим (stdin не TTY), CLI отключён`. Прочитанные строки буферизуются и выполняются после `login`, EOF бота не убивает: `[CLI] stdin закрыт (EOF)`.

### 6.4. Web GUI (`http://localhost:3000`)

- Панель статуса: HP, Food, Pos, Guard, Combat, Target — обновление 1 Гц (`broadcastStatus`).
- Кнопки: Guard, Unguard, Stop, Attack, Peace, Status.
- Поле ввода произвольной команды + кнопка «Отправить».
- Лог игрового чата и лог бота (WS-кадры `chat` и `log`).
- Индикатор подключения и авто-переподключение WebSocket.
- Доступ: `?token=<webToken>`, если токен задан; иначе только с localhost.
- Кадры: `{ type, data }` — `status`, `chat`, `log`; команды приходят как `{ type: 'command', text }`.
- Если порт занят — бот пишет `[WEB] Порт 3000 занят — Web GUI недоступен...` и продолжает играть без GUI.

## 7. Проверка функций — чек-лист

Формат: условие → как проверить → ожидаемый результат → модуль.

### Авто-подключение
- Условие: сервер доступен, `config.json` заполнен
- Как проверить: `start.bat`
- Ожидаемо: `[BOT] bindEvents вызван`, `haise вошёл`, затем `[🍖] potions registry: MISSING`
- Модуль: `bot.js` → `createBot()`, `bindEvents()`

### Reconnect с backoff
- Условие: обрыв соединения с сервером
- Как проверить: остановить сервер и запустить снова, следя за логом
- Ожидаемо: `[WARN] End: <причина>`, затем `Reconnect #1 через 5с (backoff[0])`, `Reconnect #2 через 10с (backoff[1])`, … `Reconnect #N через 120с (backoff[4])`; после успешного `login` счётчик сбрасывается
- Модуль: `bot.js` → `BACKOFF_SCHEDULE`, `backoffIndex`, `canReconnect()`

### Авто-возрождение
- Условие: бот убит мобом или игроком
- Как проверить: подвести моба к боту
- Ожидаемо: `[WARN] Смерть. Возрождаюсь...`, через ~1с бот снова в игре, охрана и следование сняты
- Модуль: `bot.js` → `bot.on('death')`, `respawnTimer`

### Авто-экипировка брони
- Условие: в инвентаре есть комплект брони лучше надетого
- Как проверить: положить боту комплект
- Ожидаемо: броня надета сама, в логе ошибок нет
- Модуль: `bot.js` → `spawn` / `playerCollect` → `bot.armorManager.equipAll()`

### Авто-экипировка оружия
- Условие: в инвентаре есть меч/топор, в руке пусто или еда
- Как проверить: положить меч и подождать 20 тиков (~1 с)
- Ожидаемо: `[INFO] [🗡] В руке: netherite_sword` (лог только при смене предмета)
- Модуль: `src/equipment.js` → `equipBestWeapon()`, `weaponScore()`

### Авто-атака враждебных мобов
- Условие: без команд в чате
- Как проверить: заспавнить зомби рядом с ботом
- Ожидаемо: `[⚔] Цель: zombie @ 3.1м` в логе за < 1 сек
- Модуль: `src/combat.js` → `autoAttack()`, `findHostileMob()`

### Бой выключается командой peace
- Условие: `Combat:OFF`
- Как проверить: `peace`, затем подождать 10 тиков
- Ожидаемо: новых строк `[⚔] Цель:` нет, в `status` — `Combat:OFF`
- Модуль: `src/commands.js` → `peace`, `src/combat.js` → `stopCombat()`

### Watchdog боя
- Условие: цель не двигается дольше 30 с
- Как проверить: заманить моба в тупик или запереть
- Ожидаемо: `[WARN] [⚔] Сторожевой таймер: бой длится >30с, цель не двигается. Сбрасываем.`
- Модуль: `src/combat.js` → `checkWatchdog()`

### Авто-еда
- Условие: голод ниже `autoEatStartAt` (14)
- Как проверить: дать боту есть и дождаться голода
- Ожидаемо: бот ест без команд, `[🍖] Съел cooked_beef` при наличии еды
- Модуль: `src/consumables.js` → `setupAutoEat()`

### Авто-лечение зельем
- Условие: `hp < autoHealThreshold` (10), в инвентаре лечебное зелье
- Как проверить: получить урон при полном здоровье
- Ожидаемо: `[INFO] [🍖] Пью Potion`, счётчик `potions 1/1` в `stats`
- Модуль: `src/consumables.js` → `autoHeal()`, `findHealingPotion()`

### Авто-лечение золотым яблоком
- Условие: `hp < autoHealCriticalThreshold` (6)
- Как проверить: получить тяжёлый урон
- Ожидаемо: `[INFO] [🍖] Съел enchanted_golden_apple`, счётчик `apples 1/1`
- Модуль: `src/consumables.js` → `autoHealInner()`, `findGoldenApple()`

### Чёрный список зелий
- Условие: зелье выпито, эффекта нет
- Как проверить: дать боту бесполезное зелье
- Ожидаемо: `[WARN] [🍖] potion использован, эффекта нет — id=24 в чёрный список (hp=0, food=17)`
- Модуль: `src/consumables.js` → `blacklistedPotionIds`

### Сброс чёрного списка
- Условие: зелья в чёрном списке
- Как проверить: `clearpotions`
- Ожидаемо: стек `clearPotionBlacklist() вызван из:`, `[🍖] Чёрный список зелий: очищен`
- Модуль: `src/consumables.js` → `clearPotionBlacklist()`

### Охрана точки
- Условие: `guard 8`
- Как проверить: `guard 8`, затем отойти боту от точки
- Ожидаемо: `[INFO] [🏰] Охраняю точку (19, 63, 39), радиус 8`, при уходе > 1.5 блока `[INFO] [🏰] Возвращаюсь к точке (N > 1.5)`
- Модуль: `src/guard.js` → `startGuard()`

### Охрана не мешает бою
- Условие: охрана активна, рядом враждебный
- Как проверить: `guard 8` + спавн зомби
- Ожидаемо: бот атакует, `[🏰] Возвращаюсь` не появляется, пока идёт бой
- Модуль: `src/guard.js` (`if (bot.pvp?.target) return;`)

### Следование за игроком
- Условие: рядом другой игрок
- Как проверить: `follow Buddy`
- Ожидаемо: `[INFO] Следую за Buddy`, бот идёт за игроком, в `status` цель следования
- Модуль: `src/follow.js` → `startFollowing()`, `bot.js` → `GoalFollow`

### Следование снимает охрану
- Условие: активна охрана
- Как проверить: `guard 8`, затем `follow Buddy`
- Ожидаемо: `[INFO] [🏰] Охрана остановлена`, в `status` — `Guard:OFF`
- Модуль: `src/commands.js` → `follow`

### Счётчики расходов
- Условие: бот что-то съел или выпил
- Как проверить: `stats`
- Ожидаемо: `🍖 potions 0/2, apples 1/1, food 0/0, blacklist=[24,25]`
- Модуль: `src/consumables.js` → `getStats()`

### Отчёт по зельям
- Условие: в инвентаре есть зелья
- Как проверить: `potions`
- Ожидаемо: `[POTIONS] registry=MISSING typeof=undefined`, `[POTIONS] всего=2`, строки `id=24 ... potionId=24`
- Модуль: `src/consumables.js` → `describePotions()`

### Статус
- Условие: бот в игре
- Как проверить: `status`
- Ожидаемо: `HP:20 Food:20 Pos:19,63,39 Guard:OFF Combat:ON Target:null`

### Остановка всего
- Условие: активны следование, охрана и бой
- Как проверить: `stop`
- Ожидаемо: `[🏰] Охрана остановлена`, `[⚔] Бой остановлен`, `Остановился`

### Броня по команде
- Условие: броня в инвентаре
- Как проверить: `armor`
- Ожидаемо: `Броня надета`

### Список команд
- Условие: бот в игре
- Как проверить: `help`

### Завершение

### Web GUI
- Условие: порт `webPort` свободен

### Heartbeat
- Условие: бот подключён дольше 30 с

### Smoke-тест
- Условие: сервер доступен, порты 3000/3100 свободны

- Модуль: `tests/smoke.js`

Итого 33 проверки. Первые 25+ покрывают 6.1 и 6.2.

## 8. Логи

- Путь: `logs/bot-YYYY-MM-DD.log` (создаётся автоматически, на каждый день свой файл; ротации по размеру нет).
- Формат: `[ISO-timestamp] [LEVEL] message`, например `[2026-10-01T11:13:55.342Z] [INFO] haise вошёл`.
- Уровни: `INFO`, `WARN`, `ERROR`, `DEBUG`, `FATAL` (последние — для необработанных ошибок).
- Теги: `[⚔]` бой, `[🗡]` оружие, `[🍖]` еда и зелья, `[🏰]` охрана, `[WEB]` Web GUI, `[CLI]` CLI, `[BOT]` бот, `[DBG]` диагностика (при `debug: true`), `[HEARTBEAT]` пульс.
- Кодировка файла — UTF-8. Консоль Windows в cp866 может показывать мусор — читать так:

```powershell
[Console]::OutputEncoding=[System.Text.Encoding]::UTF8
Get-Content logs\bot-2026-10-01.log -Encoding UTF8
```

В `start-debug.bat` используется `chcp 65001` — это снимает проблему.

## 9. Тестирование

```bash
node tests/smoke.js      # или npm test
```

Код возврата: `0` — все проверки прошли, `1` — есть провал, `2` — заняты и 3000, и 3100 (проблема окружения, не системы).

Тест сам запускает бота, проверяет подключение, WebSocket и 7 команд, затем гасит бота командой `quit`. Если порт из `config.json` занят, боту передаётся `WEB_PORT_OVERRIDE=3100` и тест переходит на 3100.

12 проверок:

| # | Проверка | Ожидаемо |
|---|----------|----------|
| 1 | `bot login` | строка `вошёл` в лог-файле |
| 2 | `bot spawn` | маркер `potions registry:` из `bot.once('spawn')` |
| 3 | `ws connect` | WebSocket на порт GUI |
| 4 | `ws status frame` | `connected=true`, целые `hp`/`food`, `pos.x`, строки `guard`/`combat` |
| 5 | `status` | `Guard:OFF Combat:ON` |
| 6 | `guard 8` | `Охрана` |
| 7 | `status` | `Guard:ON(r=8)` |
| 8 | `unguard` | `Охрана снята` |
| 9 | `status` | `Guard:OFF` |
| 10 | `stats` | `🍖` и `potions` |
| 11 | `potions` | `[POTIONS]` |
| 12 | `bot quit` | процесс бота завершился |

Сырой stdout/stderr бота пишется в `tests/smoke-bot.log` — смотреть при падении.

### Перед прогоном очистить логи

Smoke-тест читает общий суточный лог `logs/bot-ГГГГ-ММ-ДД.log`, а не изолированный файл. Если в нём уже есть строки прошлого прогона, проверки `bot login` и `bot spawn` проходят мгновенно по старым строкам, тест сразу подключается к WebSocket ещё не поднявшегося бота и падает с `FAIL ws connect — WS: connect ECONNREFUSED 127.0.0.1:3000`, убивая бота раньше, чем он что-то напишет.

```powershell
Remove-Item logs\*.log -Force
node tests/smoke.js
```

### Как добавить свою проверку

1. Открыть `tests/smoke.js`, найти массив `plan` (шаг 4–5) и добавить строку:

```js
{ cmd: 'status', expect: ['Guard:OFF'], label: 'cmd status → Guard:OFF' },
```

2. Для проверки поля кадра `status` — добавить проверку в блок `problems` после шага 3.
3. Запустить `node tests/smoke.js`, добиться `PASS N/N`.

Тест читает систему и ничего в ней не меняет: `src/`, `bot.js` и `config.json` не патчатся.

## 11. Известные ограничения

- **Лечебные зелья на 1.21.11.** В `minecraft-data` для этой версии нет реестра зелий (`[POTIONS] registry=MISSING`), `customEffects` пустой, `displayName` = `"Potion"`. Определение лечебности работает по трём уровням: реестр → `customEffects` → чёрный список. На практике срабатывает только чёрный список: зелье пробуется, если эффекта нет — `potionId` уходит в чёрный список.
- **Чёрный список живёт до реконнекта.** Сбрасывается на `bot.once('spawn')` и вручную `clearpotions`. Автосброс по `playerCollect` убран: он срабатывал синхронно с `consume()` из-за пустой `glass_bottle`.
- **Идентифицировать `potionId` 24/25 как лечебные невозможно** — в данных сервера нет их названий. Числа в `blacklist=[...]` — это внутренние id, не «зелье 24».
- **Кодировка консоли Windows cp866** ломает отображение эмодзи в терминале, но не в файле лога.
- **Бот и игрок под одним ником** — сервер выкинет одного из них.
- **`quit` пишет `Reconnect #1` в лог.** `quit` вызывает `safety.gracefulShutdown`, а флаг `isShuttingDown` в `bot.js` не выставляется, поэтому планируется reconnect. На практику это не влияет: `process.exit(0)` срабатывает через 1с.
- **Web-порт на Windows.** Из-за `SO_REUSEADDR` `listen()` не всегда отдаёт `EADDRINUSE`, когда порт держит процесс на `127.0.0.1`. Поэтому после bind делается самозапрос: если отвечает не наш сервер — пишется `[WEB] Порт 3000 занят`.
- **Ротации логов по размеру нет.** За месяц работы в `logs/` накопится 30+ файлов; удалять вручную или добавить очистку в планировщик.
- **Smoke-тест зависит от чистоты `logs/`.** Подробности и команда очистки — в разделе 9. Устранение требует изоляции лога теста (свой файл или отметка времени старта), а не обхода через `logs/`.
- **`src/data.js` в проекте отсутствует** — состояния и реестры берутся из `bot.registry` и `minecraft-data` напрямую.
- **Дроп предметов на 1.21.11 приходит как `type=other`, а не `type=object`.** Проверено через `!dumpitems`: `type=other name=item displayName=Item entityType=71`. Детект в `src/looting.js` смотрит на `name === 'item'` и `displayName`, а не на `type`. Команда `!dumpitems` оставлена как диагностика при странном поведении автоподбора.
- **Поле `entity.objectType` в `prismarine-entity` deprecated** и печатает `console.trace` с полным стеком на каждое чтение. Детект дропа в `src/looting.js` это поле не читает — используются `name` и `displayName`.
